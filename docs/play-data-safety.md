# Google Play「資料安全性」(Data safety) 表單填寫指引

> 以下是依本 App 目前程式碼整理的建議。Play 的定義會更新，送出前請對照 Play Console 內的官方說明，
> 以及 [AdMob 的資料揭露說明](https://developers.google.com/admob/android/privacy/play-data-disclosure)。

## 背景：Play 怎麼定義「收集」與「分享」
- **收集**：資料從使用者裝置傳出去（給你或第三方）。只在手機本機處理的資料**不算收集**。
- **分享**：資料傳給第三方（例如廣告 SDK 把資料送到 Google）。
- 第三方 SDK（AdMob）收集的資料，**也要算在你的 App 頭上**申報。

## 本 App 的資料流

| 資料 | 去向 | 算收集嗎 |
|---|---|---|
| 作答紀錄、錯題、複習排程、打卡 | 只在手機本機 | 否 |
| 同上（登入後備份） | 使用者自己的 Google Drive（App 資料夾） | 保守起見申報為「收集」（見下） |
| Google 帳號 email | 只存在本機顯示用；登入流程由 Google 處理 | 保守起見申報 |
| 廣告 ID、大略位置(IP)、廣告互動、診斷資料 | AdMob SDK → Google | 是，且「分享」 |

## 表單逐題建議

**1. 你的 App 是否收集或分享任何必要的使用者資料類型？** → 是（因為 AdMob）

**2. 所有使用者資料在傳輸時是否都經過加密？** → 是（全部走 HTTPS）

**3. 你是否提供讓使用者要求刪除資料的方式？** → 是
（App 內「清除本機學習資料」「刪除雲端備份」、移除 App 即刪除；隱私權政策有說明）

**4. 資料類型勾選（建議）：**

| 類別 → 項目 | 收集 | 分享 | 是否選用 | 用途 |
|---|---|---|---|---|
| 位置 → 大概位置 | ✔ | ✔ | 必要 | 廣告或行銷、分析、防詐騙/安全 （AdMob 由 IP 推估） |
| 應用程式活動 → 應用程式互動 | ✔ | ✔ | 必要 | 廣告或行銷、分析 （AdMob） |
| 應用程式資訊與效能 → 當機記錄、診斷 | ✔ | ✔ | 必要 | 分析、防詐騙 （AdMob） |
| 裝置或其他 ID | ✔ | ✔ | 必要 | 廣告或行銷、防詐騙 （AdMob 廣告 ID） |
| 應用程式活動 → 其他使用者產生的內容（學習紀錄備份） | ✔ | ✘ | **選用**（使用者自行登入才有） | 應用程式功能 |
| 個人資訊 → 電子郵件地址 | ✔ | ✘ | **選用** | 帳戶管理 / 應用程式功能 |

> 關於 Drive 備份：資料存放在使用者自己控制的 Drive，開發者無法存取。有些開發者認為不必申報；
> 但因為資料確實離開裝置，**保守申報**較不會被審查退件。

**5. 「資料是否以短暫方式處理」**：學習資料備份 → 否；AdMob 項目 → 依 AdMob 說明填寫。

## 其他上架表單相關
- **隱私權政策網址**：必填。可用 `docs/privacy-policy.md` 的 GitHub 網址，或之後放到 Cloudflare Pages。
  （記得同步修改 `gradle.properties` 的 `privacyPolicyUrl`，App 設定頁會連到這裡。）
- **廣告**：「應用程式含有廣告」選 **是**。
- **帳戶刪除要求**：本 App 沒有自建帳號系統（Google 登入只用來存取使用者自己的 Drive），一般不屬於「可建立帳戶」的 App；
  若 Play Console 仍要求，可提供隱私權政策中「如何刪除你的資料」段落的網址。
- **廣告 ID 宣告**（Play Console → 應用程式內容 → 廣告 ID）：選「是，使用廣告 ID」，用途勾「廣告或行銷」「分析」「防詐騙」。
- **目標年齡與內容**：見 `docs/children-and-ads.md`。
